# code-to-gate v1.6.0 リリースノート

公開状態は[`docs/distribution-status.md`](../distribution-status.md)で管理します。

## 主な変更

### 公開契約とseverity policy

- 公開artifact APIは `ctg/v1` を継続し、v1の互換性を維持します。既存の
  `ctg/v1alpha1`も後方互換のため受け付けます。
- policyに任意の順序付き `severity_overrides` を追加しました。`rule_id`、path、categoryの
  selectorはANDで評価し、最初に一致した設定を適用します。camelCase alias、severity enum、
  reason、globの検証を行い、不正な設定はfail closedします。
- raw findingsは検出時severityを保持し、effective findings、blocking、DSL、count cap、
  risk・test・report出力は適用後severityにそろえます。元severity、適用理由、該当selectorを
  証跡に残し、readinessのcurrent/baselineも同じpolicyで正規化します。
- `diff --policy`にも同じseverity評価を接続し、raw/effective成果物、件数、audit、終了判定の
  不一致を防ぎます。

### precision-review

- private運用JSON契約 `precision-review@v1` と、ローカル完結の
  `precision-review --from findings.json --review review.json --out review.html` を追加しました。
- findings生bytesのSHA-256、run ID、repo root/revision/full SHA、finding ID・rule ID・fingerprint・
  evidence hashをbindingとして検証します。順序変更は許可しますが、重複、欠落、未知ID、改竄、
  repoやcommitの不一致は拒否します。
- HTML画面では根拠、取得可能なbound commitのコード、検索、rule/category/classification filter、
  進捗、ページング、TP/FP/Uncertain/AcceptedDesign分類、日本語コメント、JSON保存・読込再開を
  提供します。AI reviewerとhuman reviewerを区別し、AI案や未判定を人手精度の根拠として扱いません。
- コード表示は明示 `--repo` のみを対象にし、dirty repo、unknownまたは不一致のcommit、repo外path、
  UTF-8 bytes・ファイル数・行数の上限超過では理由を示して本文を表示しません。入力findings/reviewは
  `--force`でも出力先として上書きできず、既存出力も通常は保護します。

### 証跡、CI、Birdseye

- 実行ごとのrun ID生成を衝突しにくくし、継承artifact IDとagent requestの再利用を維持しました。
  graph cache hitではsource identityを変えず、実行metadataだけを更新します。
- 決定的なBirdseye index/capsule生成、source capsuleのdrift check、roadmap台帳の完了・参照検査を
  整備しました。Birdseyeはsource line endingを正規化し、Windows/Linux間の差を抑えます。
- maintenance test、Birdseye freshness、roadmap completion、文書参照をPR coverageとRelease
  analyzeのCIへ接続しました。PR用diff policyとreadiness用full policyを分離しています。
- MarkdownとHTML Viewerに元severity、適用severity、調整理由を表示し、public profileではprivate
  reviewの詳細を省きます。表示用scriptへの本文露出と抑制後の件数不一致も修正しました。

## セキュリティと証跡の改善（PR #17の変更）

- v1.5.1から継続するSemgrep/Gitleaksの固定toolchain metadata、CycloneDX SBOM、golden
  regressionをrelease gateとして検証し、scanner provenanceとhigh/critical npm auditの確認を維持します。
- evidence bundleの抽出先外path、Windows形式のtraversal、正規化後のdestination collisionを拒否し、
  Docker commandはshell文字列ではなくargvで実行します。timeout時はplugin process treeを終了します。
- literal-awareなdebt comment、secret assignment、router anchored rate-limit、SQL keyword boundary、
  JavaScript/TypeScript function countのrule precisionを修正しました。`fs.existsSync`や
  `Buffer()`の誤検出も修正しています。
- QEG 0.2 wire contract、readiness由来の条件、hash-backedな事前生成artifact参照、security scope付き
  SARIF exportを修正しました。Python cacheやrepository-local生成物はbounded discoveryから除外します。
